REST API

AuthenticationWebsitesDeploymentsJobsOther endpoints

The dashboard is built on a JSON REST API under /api/v1. Anything you can click, you can script.

Authentication

Use either a session token from the login endpoint (valid for 24 hours) or the API key from Settings → Admin API Key:

# Session token
curl -s -X POST https://panel.example.com/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"…"}'
# → {"success":true,"token":"…"}

curl -s https://panel.example.com/api/v1/sites -H 'Authorization: Bearer TOKEN'

# API key
curl -s https://panel.example.com/api/v1/sites -H 'X-API-Key: YOUR_API_KEY'

The API key has full control of the server. Keep it out of repositories and rotate it in Settings if it leaks.

Websites

Method & pathDescription
GET /sitesAll websites with status, plus unmanaged nginx sites
GET /sites/suggest?name=&domain=&repo=&type=Suggested name, folder, free port and PHP version
POST /sites/inspect{ gitUrl, branch } → branches, detected stack, commands, PHP version
POST /sitesCreate a website → { site, jobId }
GET /sites/:idDetails, health, runtime and database
PUT /sites/:idUpdate settings (branch, commands, port…)
PUT /sites/:id/domains{ domains: [...] }
POST /sites/:id/sslIssue HTTPS → { jobId }
GET / PUT /sites/:id/envRead or write .env
POST /sites/:id/app/:actionstart, stop or restart the app
POST /sites/:id/backupsBack up now
POST /sites/:id/deleteDelete (optionally with files and database) → { jobId }

Create a Next.js website from Git:

curl -s -X POST https://panel.example.com/api/v1/sites \
  -H 'X-API-Key: YOUR_API_KEY' -H 'Content-Type: application/json' \
  -d '{
    "source": "git",
    "type": "next",
    "name": "shop",
    "gitUrl": "https://github.com/you/shop.git",
    "branch": "main",
    "domains": ["shop.example.com"],
    "ssl": true
  }'

source is git, wordpress, empty or proxy. type is one of node, next, react, laravel, php, wordpress, static, python or proxy. Omitted values such as deployPath, port, webRoot, deployScript, startCommand and phpVersion are filled in from the repository.

Deployments

Method & pathDescription
POST /sites/:id/deployDeploy now → { jobId, deployId }; 409 if one is running
POST /sites/:id/rollback{ commit } deploy an earlier commit
GET /sites/:id/deploymentsHistory, newest first
GET /sites/:id/deployments/:deployId/logLog of one deployment
GET /sites/:id/git/pendingCommits not deployed yet
POST /sites/:id/webhook{ enabled, rotate } push-to-deploy
POST /hooks/deploy/:idThe webhook endpoint for Git hosts (signed, no API key)

Deploy from a CI pipeline, for example GitHub Actions:

curl -fsS -X POST "https://panel.example.com/api/v1/sites/$SITE_ID/deploy" \
  -H "X-API-Key: $AUTSPANEL_API_KEY"

Jobs

Long operations return a jobId. Poll it for status, steps and new output:

Method & pathDescription
GET /jobsRecent jobs
GET /jobs/:id?offset=NStatus, steps and output after character N
POST /jobs/:id/cancelStop a running job

Other endpoints

The other modules follow the same pattern: /databases, /php, /backups, /cron, /firewall, /ssh, /nginx, /files, /mail, /monitor, /system and /settings. Each route file in server/routes documents its endpoints in comments.
