Troubleshooting

Most problems show a clear message in the job log. If not, start here.

The dashboard doesn't load

systemctl status vps-backup-manager
ss -tulpn | grep 9090
ufw status
journalctl -u vps-backup-manager -n 100

Also check your provider's cloud firewall (for example Contabo, Hetzner or AWS security groups) allows the port.

Can't log in

  • The login comes from ADMIN_EMAIL and ADMIN_PASSWORD in /opt/backup-vps/.env. Restart the service after changing it: systemctl restart vps-backup-manager.
  • “Too many failed logins” clears itself after 15 minutes.

A deployment failed

  • Open the deployment in the history and read the step that failed — the log shows each command as it runs.
  • Pull failed: the repository can't be reached (add a deploy key for private repositories), or files were changed on the server — use Discard server changes.
  • Build failed: run the same command in the Terminal inside the site folder. Out of memory? Add swap or a bigger plan.
  • Health check failed: the app crashed or listens on a different port. Make sure it uses the PORT environment variable; the App tab shows the error log.

502 Bad Gateway

  • Node.js / Python: the app is stopped or crashed — check the App tab.
  • PHP: the site's PHP-FPM version isn't running — start it on the PHP page or switch versions.

HTTPS can't be issued

  • Every domain on the website must point to this server — check the DNS status on the Domains & SSL tab. Remove domains that don't.
  • Port 80 must be open to the internet for the HTTP challenge.
  • Behind Cloudflare's proxy? Turn the proxy off while issuing, or use an origin certificate.

Backups fail

  • Google Drive 403 storageQuotaExceeded: service accounts can't store files on personal drives; use an OAuth token or a shared drive.
  • Use Test connection in Settings for each destination to see rclone's output.

Cron jobs don't run

  • The Cron page warns if the cron service is stopped — click Start cron.
  • Check /var/log/vps-panel-cron.log and use Run to test a job.
  • Custom commands run with a minimal PATH: use absolute paths such as /usr/bin/php8.3 and write % as \%.

Terminal in basic mode

The node-pty module didn't compile. Install build tools and reinstall:

apt install -y build-essential python3
cd /opt/backup-vps/server && npm install
systemctl restart vps-backup-manager

Couldn't check for updates

The server can't reach the Git remote — check its network, or add a deploy key if your copy comes from a private fork. “Files were edited on the server” means tracked files were changed by hand: run git status in /opt/backup-vps and commit or revert them.

Still stuck? Open an issue with the job log, or email tm.aashish1@gmail.com.
