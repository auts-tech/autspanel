Security

On this pageSecure the panelFirewallSSH keysServices and portsSecurity model

AutsPanel runs as root and includes a terminal and file manager, so the panel itself is the most important thing to protect.

Secure the panel

  • Use a long, unique ADMIN_PASSWORD and a random SESSION_SECRET in .env.
  • Serve the panel over HTTPS on a domain and set HOST=127.0.0.1 so port 9090 is closed (see Installation).
  • Logins are rate-limited: 10 failures per IP in 15 minutes block further attempts.
  • Sessions expire after 24 hours.

Firewall

Security → Firewall manages UFW. When you click Turn on, AutsPanel first allows SSH (on your real SSH port) and the way you reach the panel. Then add rules:

  • Quick rules for Web (HTTP + HTTPS) and Email (SMTP, IMAP).
  • Allow, deny, reject or limit a port or range over TCP, UDP or both, optionally only from an IP or network.
  • Block IP — the rule is placed first so it takes effect immediately.

Rules that would block SSH, and deleting the last SSH rule, are refused.

SSH keys

Security → SSH Keys lists the keys that can log in as root, with fingerprints; add or remove keys there. The same page generates the server's deploy key (ed25519) for private Git repositories with a Test the connection button for GitHub, GitLab and Bitbucket.

Once your SSH key works, consider turning off password logins in /etc/ssh/sshd_config (PasswordAuthentication no).

Services and ports

Services lists systemd services such as nginx, MariaDB, PHP-FPM, cron and Docker: start, stop, restart, enable at boot and read their journal. Ports & Processes shows every listening port, whether it is public, whether the firewall allows it, and which website, app or service it belongs to.

Security model

  • All API routes under /api/v1 require a session token or the API key.
  • The only unauthenticated endpoint is the per-website deploy webhook. It is off until you enable it and checks the website's own secret (HMAC signature or GitLab token).
  • Names, domains, paths, branches, ports and IP addresses are validated before use, and passed to tools as separate arguments wherever possible.
  • Database and mail credentials are stored in files readable only by root (mode 0600).
